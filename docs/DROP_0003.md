# DROP 0003 — Adapter Engine

DROP 0003 turns Chaos Pass from a filesystem stress harness into a target-aware execution engine.

## Added

- read-only target fingerprinting;
- adapter registry and adapter stacking;
- persona-to-adapter attack planning;
- separate auto actions and external-driver actions;
- generic filesystem adapter;
- Git repository adapter;
- Python project adapter;
- Node project adapter;
- Rust project adapter;
- opaque executable detection;
- explicit configured CLI adapter;
- external playbook-driver protocol;
- `inspect-target` and `plan` CLI commands;
- persisted process evidence;
- process cwd confinement;
- disposable HOME/AppData/temp/package-manager state;
- inherited secret/token stripping;
- best-effort network denial by default;
- process-tree termination on timeout;
- symlink and Windows junction escape detection;
- blocked-run reports when safe isolation cannot be created;
- expanded adapter/safety tests.

## Deliberate constraints

Chaos Pass still refuses to auto-launch opaque executables or arbitrary project test commands without explicit safe probes. GUI actions are emitted for an external authorized driver rather than silently skipped or falsely marked complete.

## Validation

Before release, DROP 0003 was dogfooded against Chaos Pass itself with deterministic seed `3003`.

Final self-pass result on Windows:

- CATASTROPHIC: 0
- BREAK: 0
- BEND: 1 — the sandbox cleanly characterized the local filesystem path-length boundary instead of crashing the harness
- BLOCKED: 6 — target-specific GUI/security/persistence/state checks requiring a stronger adapter/driver
- SURVIVED: 39
- original integrity: PASS

The automated unit/integration suite contains 24 passing tests on the development machine; one additional symlink test is skipped there because the Windows account lacks symlink-creation privilege. Windows junction escape coverage runs and passes.
